# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Overview

Tokei is a SwiftUI world clock. Saved time zones are markers on a Metal-rendered 3D globe with a live day/night terminator; a time tape shifts the displayed moment. The globe has themes (`SceneStyle`): a photo-real ray-traced Earth and several artistic, deliberately non-geographic mesh globes. A theme restyles the whole app, not only the globe. The Weather theme draws schematic clouds and precipitation from NOAA GFS model data, fetched as discrete snapshots for the settled displayed time. A WidgetKit extension shows the same cities, the same shift and a day/night map. The deployment target in the project file is recent enough that Liquid Glass and other current SwiftUI APIs are used without availability checks.

## Build

- Xcode project only, no package managers. Scheme `tokei` builds the app and embeds `tokeiWidgetExtension`.
- CLI: `xcodebuild -project tokei.xcodeproj -scheme tokei -destination 'platform=iOS Simulator,name=<device>' build`.
- No test target. Verify in the simulator; widgets are added from the home-screen widget gallery.
- An offline Metal harness (gitignored, `.claude/duck/scene-style/harness/`) renders any theme at fixed dates and cameras through the app's own `GlobeRenderer`: `STYLE=<raw value> render.sh [scene…]`. Globe files that import UIKit or SwiftUI views must be listed in its exclude list, which is why interface views live in `tokei/Interface/`.

## Layout

- `Shared/` is a file-system-synchronized folder attached to both targets: the `Zone` model, App Group persistence (`ZoneStorage`), time formatting (`ZoneClock`), sun ephemeris (`SolarPosition`), label collision placement (`LabelPlacer`) and the palette. Anything the widget needs lives here.
- `tokei/Globe/` draws the globe with Metal, no RealityKit.
  - `Shaders/`: `GlobeShared.h` (shared structs and `static inline` helpers), `Realistic.metal` (a full-screen fragment that ray-traces an analytic sphere), `Mesh.metal` (the vertex path shared by every mesh theme, plus the relief compute kernel) and one fragment file per mesh theme.
  - A theme is a `SceneStyle` case mapped to a `SceneLook` in `Looks/<Name>Look.swift`: backdrop, accent, `EffectTuning`, sound timbre and, for mesh themes, a `MeshLook` naming its fragment function, its shape and its parameter struct (mirrored field for field in its `.metal` file, bound at fragment `buffer(1)`). `GlobeRenderer` builds one pipeline per mesh fragment. A mesh theme may also name a full-screen background fragment (same parameter struct), drawn before the globe in the same pass; it depends only on the camera, so it never animates on its own. The style rides in `GlobeFrame`, so switching redraws like any other frame change. `Looks/InterfaceLook.swift` holds each theme's interface (typography, surfaces, chips, markers, tape, picker swatch).
  - Mesh terrain is generated at load from the water mask, not bundled: a coast signed distance field (`CoastDistance`), then per-shape heights in `Shapes/` as functions of that distance (`TerrainProfile` plus a smooth inland field; the glacier shape adds seeded mountain ranges from `MountainRange`, geometry only). The active theme's shape is built before the reveal, the others in the background. The mesh is a camera-dependent quadtree on the cube faces (`ToySurface`, `TerrainTree`, `TerrainGrid`) whose vertices are computed on the GPU; the relief normal map is computed on the GPU too.
- `tokei/Weather/` is the only networking in the app: the GFS client (idx sidecar plus capped, streamed HTTP range requests on the public NOAA mirrors: AWS first, then Google Cloud and Azure), a restricted GRIB2 decoder (grid 3.0, packing 5.3 only), forecast cycle and lead selection, the disk and memory cache, `WeatherFeed` (state and refresh) and `CloudMap`, which bakes the cloud mask, precipitation and precipitation type into one equirect texture. The widget does not use it.
- `tokei/Clock/` holds the stores, the time tape, the scrubber panel, the city list and the city picker. `tokei/Interface/` holds the themed interface views and the theme tray.
- `tokei/Feedback/` holds sound and haptics: cues, the code-generated sounds (`SoundSynth`, and `SoundLayers` for layered designs), the audio engine and the Core Haptics wobble and grains.
- `tokeiWidget/` holds the timeline provider, the intents and the widget views.

## Rules that are easy to break

- One displayed time: `now + shift`. The sun, marker chips, list rows and widget entries all derive from that single date. Never call `Date()` inside formatting helpers or views.
- One reference zone: offsets, day labels, the tape and "Show my time zone" compare against `ClockStore.homeZone` (in widgets, `ClockEntry.homeZone`). It follows the device unless the user picked a zone in the Cities sheet. Never compare against `TimeZone.current` directly.
- The globe is Earth-fixed: the camera orbits a still Earth and the sun direction moves with time. The latitude/longitude ↔ vector convention is duplicated in the shaders (`surfaceCoordinates`), in `GeoPoint.unitVector` and in the equirect sampling of the terrain generators; change all or none.
- `GlobeFrame` is the immutable per-frame snapshot used both for shader uniforms and for projecting SwiftUI marker chips. Chips must stay unanimated in position, or they drift off their cities.
- `GlobeLayerView` draws on demand in `layoutSubviews` and presents with the Core Animation transaction, so a SwiftUI update and its Metal frame land together. Continuous motion (inertia, fly-to, shift glide) is a pure function of time inside `TimelineView(.animation)`; `.task(id:)` settles it. Nothing renders while idle except the minute tick, so no shader may animate on its own clock.
- The realistic atmosphere is single scattering with a precomputed transmittance LUT that includes the planet shadow. Clouds are a thin shell above the ground lit through the same LUT; relief is slope-only hillshade from the elevation map. Twilight warmth, moonlight and the reduced haze over the night side are deliberate art terms, not physics. Every fragment encodes sRGB itself into a non-sRGB drawable after tone mapping (`finishColor`); do not add a second gamma.
- Surface texture sampling uses explicit gradients taken before any branch, because derivatives are undefined in divergent control flow. New taps and `fwidth` terms reuse or join that hoisted block.
- Mesh `texture(2)` is the coast signed distance field in degrees, positive on land; fragments antialias the coast with `coastCoverage`. Shape heights are zero at the coast so the geometric edge sits on the colour edge. Relief normals in `texture(3)` must be normalized after sampling.
- Mesh day/night gates read the radial direction of the surface point only; the displaced shape and its normals feed material shading, never the terminator or city-light gating.
- The mesh vertex path reproduces `GlobeFrame.project` exactly, and `MarkerLayout` lifts each city onto the drawn surface through `ToySurface.radius(along:in:)`, which replays the same level-of-detail selection and triangle. A change to the camera projection, the mesh or the LOD has to reach both sides, or chips drift off their cities.
- Interaction effects (press dent and squash, city pop and ripple, fling stretch, inflate, fly-to arc, dent follow) are time-parameterised records in `SceneEffects`, evaluated once per frame into `GlobeFrame.effects`, like camera motion. Each theme has its own `EffectTuning`. The shaders and `EffectSnapshot.place` (which positions chips) apply the same displacement formulas: change both or neither.
- `GlobeTouch` is the single decision point between rotation and surface drags: the SwiftUI rotation drag and the UIKit zero-duration press see the same touches in no guaranteed order, so the hold is resolved from timestamps by whichever asks first. Hold then drag carves snow or drags the dent; quick drags rotate.
- Snow footprints and finger trails live in `SnowCover`: a CPU-written R16F map of when each spot was last disturbed, relative to the cover's epoch. Trails store times up to one recovery period in the future, so refill stays a pure function of the snow clock in `EffectUniforms.state.w` (`smoothstep(0, R, clock − value)`); the map is cleared when the `SceneEffects.snow` record settles, so no per-frame decay pass exists.
- The realistic fragment is compiled twice through a function constant. The effect-free variant draws every idle frame; the renderer switches to the effects variant only while an effect is live.
- Sounds belong to mesh themes, each theme's timbre in its look file, and are generated in code with seeded randomness, so output is deterministic per variant. They play through an `.ambient` audio engine that runs only while such a theme is active, sound is on and the app is in the foreground, and pauses after a short silence. `SoundOutput` owns the engine and the session on its own serial queue. A cold start or resume blocks for tens of milliseconds, and on the main thread that stall lands on the touch that triggered the sound. Adding a `FeedbackCue.Kind` needs a base voice in `SoundSynth.voice(for:)`. Discrete haptics go through `SceneModel.cue` into `.sensoryFeedback`; the release wobble and carve grains use Core Haptics. Neither can be judged in the simulator.
- Theme colours are authored as sRGB hex and uploaded linear. A mesh theme's backdrop is also the SwiftUI and layer background and the mesh pass's clear colour. Interface colours derive from the theme's backdrop and accent at runtime, except the theme-tray swatches, which copy palette colours and must be updated when a palette changes. Widgets keep `Color.sunlight`.
- `SceneStyle` raw values are persisted in standard defaults: never rename a shipped one.
- Globe textures are bundle resources in `tokei/Resources` (NASA Blue Marble / Black Marble, clouds and elevation, plus a water mask) uploaded with mipmaps; the widget has its own small map images in its asset catalog.
- The stored JSON shape of `Zone` must stay decodable; suite name and keys live in `ZoneStorage`. The shift is a persisted relative offset shared with widgets.
- Every mutation of App Group data calls `WidgetCenter.shared.reloadAllTimelines()`. Scrubbing persists only when the glide settles, not per drag sample. App-only preferences such as the theme live in standard defaults and do not reload widgets.
- Widget kind identifiers (in `TokeiWidgets.swift`) are placed on users' home screens: never rename or remove them. Intent type names are referenced by the system too.
- Widget timelines are minute-aligned and self-contained. The night mask is computed on the CPU per entry (`NightMask`); the extension does no GPU work.
- `tokei://zone/<uuid>` opens the app focused on that city (used by widget rows).
- Weather follows the one-displayed-time rule with discrete frames: the target is the settled `now + shift` rounded to the model step, held during scrubs and glides, never fetched per drag sample. Fetching happens only while the weather theme is active and the app is in the foreground. Missing data is shown as a status, never as a cloudless globe.
- The cloud shell is a second mesh draw after the terrain (opaque cutout through alpha-to-coverage). Its vertices go through the same placement helpers as the terrain in `Mesh.metal`, mirrored on the CPU by `EffectSnapshot.place(_:lift:)`; `CloudShell.lift` is the one shell-radius function for the shell, picking and chip hoisting.
- The cloud mask, puff noise included, is baked on the CPU into the weather texture. The cloud shader and `CloudPresence` (chip hoisting, cloud taps) read the same bytes with the same bilinear rule, and the shader's disturbance refill matches `SnowCover.level`. Change one side and the other together. Chip eligibility (facing, fade) uses the ground point; only the projected anchor is hoisted, and `LabelPlacer` runs on hoisted anchors.
- `SnowCover` is shared by every theme with `SnowSettings` and is reset on every style change. Mesh `texture(5)` is the weather map for every mesh fragment (a placeholder without data).
